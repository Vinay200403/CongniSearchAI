# CogniSearch AI

Document Q&A application. Upload PDF, DOCX, TXT, or Markdown files and ask
questions grounded in their content. Built with a Flask REST API and a
FAISS vector index for fast, contextual semantic search.

This matches the project as described on the portfolio site: *"a document
Q&A application combining Flask REST APIs with a FAISS/ChromaDB indexing
pipeline for fast, contextual semantic search, with a modular backend for
upload, indexing, and query."*

## How it works

```
 upload → extract text → chunk (with overlap) → embed → FAISS index
                                                              │
 question → embed → FAISS similarity search ─────────────────┘
                          │
                 top-k relevant chunks
                          │
        ┌─────────────────┴─────────────────┐
        │                                    │
  OPENAI_API_KEY set               OPENAI_API_KEY not set
        │                                    │
  LLM generates a grounded          Top matching chunks
  answer citing sources             returned directly
  (full RAG)                        (retrieval-only mode)
```

The embedding backend is pluggable (`core/embeddings.py`) with three
interchangeable options, auto-selected in this priority order:

1. **Gemini** — if `GEMINI_API_KEY` is set. Uses Google's
   `gemini-embedding-001` for embeddings and `gemini-2.5-flash` to
   generate a grounded answer (full RAG).
2. **OpenAI** — if `OPENAI_API_KEY` is set (and no Gemini key). Uses
   `text-embedding-3-small` + `gpt-4o-mini`.
3. **Local** — no key needed. Falls back to a `HashingVectorizer`
   (scikit-learn) so the whole app still runs and is demoable with
   zero API cost, zero external calls, and no large model download.
   Search becomes keyword/frequency-driven rather than deep semantic
   search in this mode, but the pipeline (chunk → embed → index →
   retrieve) is identical either way.

> **Note on Gemini specifically:** a **Gemini Pro app subscription**
> (the consumer product at gemini.google.com) is a different thing from
> **Gemini API access**. It does not include free API credits. To use
> the Gemini backend here, get a separate, free API key from
> [Google AI Studio](https://aistudio.google.com) — the Gemini API has
> its own free tier independent of any app subscription.

This means the project runs immediately for grading/demoing, and
upgrades to full generative RAG the moment you add either key — no
code changes needed.

## Project structure

```
CogniSearch-AI/
├── app.py                  # Flask app entry point
├── config.py                # All paths, tunables, feature flags
├── core/
│   ├── document_loader.py   # PDF/DOCX/TXT/MD → plain text
│   ├── chunker.py           # Sliding-window text chunking
│   ├── embeddings.py        # Pluggable OpenAI / local embedder
│   ├── vector_store.py       # FAISS index + metadata persistence
│   └── qa_engine.py         # Retrieval + optional answer generation
├── routes/
│   └── api.py                # REST endpoints
├── templates/index.html      # Frontend
├── static/style.css, script.js
├── uploads/                  # Scratch space during upload (auto-cleared)
└── data/                     # Persisted FAISS index + metadata
```

## Setup

```bash
git clone <your-repo-url>
cd CogniSearch-AI
python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

Open **http://localhost:5000**

### Optional: enable full RAG with Gemini (free tier available)

```bash
export GEMINI_API_KEY="AIza..."   # get one at https://aistudio.google.com
python app.py
```

### Optional: enable full RAG with OpenAI

```bash
export OPENAI_API_KEY="sk-..."    # Windows: set OPENAI_API_KEY=sk-...
python app.py
```

With a key set, `/api/health` will report `"generation_enabled": true`
and answers will be generated by the LLM instead of returned as raw
retrieved passages. If both keys are set, Gemini takes priority.

## REST API

| Method | Endpoint              | Description                          |
|--------|------------------------|---------------------------------------|
| GET    | `/api/health`           | Backend status, active embedder       |
| POST   | `/api/upload`           | Upload + index a document (`file` field) |
| POST   | `/api/query`            | `{"question": "..."}` → answer + sources |
| GET    | `/api/documents`        | List indexed documents                |
| DELETE | `/api/documents/<id>`   | Remove a document from the index      |

Example:
```bash
curl -F "file=@report.pdf" http://localhost:5000/api/upload

curl -X POST -H "Content-Type: application/json" \
  -d '{"question": "What was the Q3 revenue?"}' \
  http://localhost:5000/api/query
```

## Deploying a live demo

For a link you can put in your LinkedIn Featured section or portfolio:

- **Render** or **Railway**: connect the repo, set the start command to
  `gunicorn app:app`, and optionally add `OPENAI_API_KEY` as an
  environment variable.
- Free tiers on both are enough for a demo — the local embedding fallback
  means it works even without setting an API key.

## Known limitations / next steps

- No OCR — scanned/image-only PDFs won't extract text yet.
- FAISS index is a single flat index (exact search); fine at demo scale,
  would move to an IVF/HNSW index for large corpora.
- No auth — anyone with the URL can upload/query/delete. Add an API key
  or login before deploying somewhere public with real documents.
- Local fallback embedder is frequency-based, not deep semantic — good
  enough for keyword-heavy queries, weaker on paraphrased questions
  compared to the OpenAI-backed mode.
